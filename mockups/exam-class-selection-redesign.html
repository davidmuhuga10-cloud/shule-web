Before What's happening today

The checkbox / class-name / "min. learning areas" row squeezes the class name into a narrow flexible column next to a fixed-width input box. On a typical modal width, "Grade 1" and "Grade 5" don't have room to sit on one line, so they wrap mid-word — reading as "G" / "1" instead of "Grade 1".

Root cause: the name column and the input column compete for the same limited width on every row, whether or not that class is even selected — the input is shown (and reserved space for) even for classes nobody has ticked.

After Proposed redesign

Classes become selectable cards in a responsive grid instead of table rows — the full class name always has as much room as it needs, because there's no competing fixed-width input next to it. The "min. learning areas" field only appears inside a card once it's selected, so unselected classes stay lightweight and scannable. Classes are grouped by education level (Primary / Junior Secondary / Senior Secondary) — the same grouping and chip convention Subjects already uses under Classes & Streams, so this isn't a new pattern for the app, just this screen adopting one that's already proven here. A search box and Select all / Clear shortcuts are added for schools with a long class list.

Why this structure, not just an alignment patch

  • Names can never truncate again. A card sized to its own grid cell has no neighboring column fighting it for width — "Grade 11 Arts & Sports Science" gets exactly as much room as it needs, same as "Grade 1".
  • The layout stops feeling cramped because most cards (the unselected ones) show nothing but a checkbox and a name — the "min. learning areas" control, which is only relevant to a fraction of classes on any given exam, no longer takes up permanent real estate on every row.
  • Reuses an existing, working pattern. The Subjects screen under Classes & Streams already groups chips by education level with this same uppercase-label convention — carrying that into Exam Desk keeps the app internally consistent instead of introducing a one-off component.
  • Scales to schools with many classes. The search box and Select all / Clear actions matter once a school has 12+ classes across three levels — scrolling a long checkbox list to find one class is exactly the kind of friction a chip/card grid with search avoids.
  • Locked classes (already has marks) are visually distinct — greyed check, explicit "has marks recorded" note — rather than just a disabled checkbox that's easy to miss the reason for.
